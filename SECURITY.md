# Security

Moni is an early personal-testing project, not a bank or payment verifier. Security fixes and careful reports are welcome.

Do not post secrets, real financial records, notification contents, tokens, databases or exploitable vulnerability details in a public issue. Use GitHub's private vulnerability reporting when available, or contact the maintainer privately through their GitHub profile to arrange a private report. Public issues are suitable for non-sensitive configuration questions and redacted bug reports.

If a secret has been exposed, revoke or rotate it at its provider. Deleting a file or rewriting Git history does not revoke a secret.

The Android database and candidate review queue use device-backed encryption. JSON exports and the browser preview are unencrypted. Drive backup is protected by Google account access, not end-to-end encryption by Moni. Notification access is broad at the operating-system level; the app's limited filters do not change Android's permission scope.

No production signing key, OAuth client secret, user database, backup or personal screenshot is part of the public source. Build with your own signing identity and Google OAuth configuration before distributing. The development signing key generated by Android tooling is not a production identity.
